# A tree that has to pay for itself

Not a fractal and not an L-system. Every shoot is paid for out of what the leaves earned that season, against the cost of keeping those leaves alive and of building the new wood. Twenty-two years of that, drawn as a pencil study on cream paper with a person standing beside it for scale.

## Running it

Open `index.html` in a browser. That is the whole of it - one file, no build,
no server, no keys. It is written for a 4K screen and scales down.

Press `i` for the parameters it is running, and the arrows appear if you move
a pointer. A standalone copy starts itself again when a run ends; add
`?pin` to the URL to keep the current run going instead.

## What it is doing

- Growth rate is an OUTPUT here, never a setting. Where the model grows too slowly the answer is a missing mechanism, not a coefficient to raise. Maintenance is charged per leaf and new wood is charged when it is built; wood already standing is free, which is a simplification the full model does not make.
- The drawing is not a render of the geometry. Each stroke is a lineage walked from a tip all the way down to the ground, and thickness is built up by drawing over the same path again and again rather than by setting a line width - so a trunk is thick because a hundred tips route through it, which is also why it is thick in life.
- Six looks, drawn from the seed: summer maple, backlit, foliage mass, autumn glow, ink sketch and winter bare. Two of them have no leaves at all, so about one showing in five is bare wood - and the ink sketch drops the ground and the shadow with them. Camera elevation and orbit direction are drawn per run too.
- This is an openly reduced port of a much larger model. The phloem transport, the 25-direction light field, auxin, roots and starch reserves are all cut; what is kept is the carbon budget, the branching rules and the pipe model that sets how thick a branch has to be to feed what is above it.
